# 146：大索引内存优化与持久化降峰值

日期：2026-10-22。汇总 2026-10-21 至 2026-10-22 的多轮优化；主要实现已包含于 `86425e0`、`1a01e4c`、`f79f565`。

## 当前实现

### 共享目录、名称和压缩倒排表

- `DirectoryPool` 按目录组件和父目录 ID 保存共享路径前缀，原始路径与小写路径共用目录树；路径按需还原。Unicode 上下文大小写、非法 UTF-8 等情况保留覆盖数据，维持原有匹配语义。
- `FoldedNamePool` 合并原始名称与小写名称，相同时共享字节，不同时保留独立偏移和长度，支持大小写转换后 UTF-8 长度变化。
- 名称 trigram 倒排表最终使用 **varint 差分编码 + 稀疏检查点**。两遍统计后准确分配编码字节与检查点容量，顺序解码，增删时只调整相邻差分及后续检查点。
- 取消常驻路径 trigram 倒排表，保留名称 trigram、扩展名索引和目录到记录映射。路径条件改用去重目录匹配后展开记录，详见 [147：算法更新](147-query-and-prefix-removal.md)。
- 早期采用过固定 24 位记录号并按需升级 32 位的倒排表；它已被差分编码替代，不是当前最终布局。

### 路径定位与元数据列

- 路径定位由保存完整字符串的查找表，经过 hash/编号 B-tree，最终改为 `PathRecordTable` 开放寻址表：每槽仅保存 **4 字节记录号**，键从规范目录 ID 和小写名称计算，完整比较区分碰撞，删除采用后移法。
- 拼接后路径相同的目录共用规范号 `dirCanon_`，保留大小写不敏感的路径去重语义；清空记录名称之前先移出路径表。
- `DirRecordMap` 用 CSR 连续记录段和追加尾列表代替每目录一个小 vector；遍历时跳过墓碑，保持记录号升序。
- `sizes_`、`modTimes_` 常见值使用 32 位列，超范围值和转义值进入稀疏旁表；超过 4 GiB 的文件、负数时间和其他边界值仍保留精确值。
- 引擎不再常驻保存没有搜索消费者的 inode、设备号两列，相应读取接口返回 **0**。v6 文件保留这两个区段，保存时填 0，加载时跳过；扫描器及 WAL 写入路径不变。中间版本的设备号字典编码已移除。

### 加载、保存与结果对象

- 大型数组按受控比例增长，减少默认倍增；建索引后收紧容量，处理完成的临时列及时释放。
- v6 保存通过共享读视图借用已有列，流式还原字符串和累计 CRC，避免完整快照副本及大块 CRC 缓冲。写入线程在 mutation gate 外排队，降低写者等待连带阻塞搜索的影响；保存仍可能延后文件更新。
- 启动转换期间只读映射输入字符串池，完成转换后释放；常驻索引仍是内存结构。v6 磁盘编码保持兼容，既有 CRC、边界校验及 I/O 错误处理保留。
- 最近文件缓存仅用有界堆保留最优 200 项；GUI 的 `MEQuerySnapshot` 保留编号及所属引擎，首批仅生成 100 个结果对象，随后按页获取，避免一次物化最多 10,000 个完整结果。
- GUI 通过 `LSEnvironment` 设置 `MallocLargeCache=0`；daemon 在未显式设置时通过 re-exec 应用该配置，减少已释放的大块临时内存被分配器继续保留。该配置依赖系统分配器行为；从 Xcode 直接调试运行需单独配置环境变量。

保存负载也有改善与取舍：

- 第二轮固定 100 次并发更新：采样峰值 **3424.83 → 2472.92 MiB**，保存 **262.5 → 120.2 ms**，保存期间搜索最长耗时 **123.2 → 0.89 ms**。
- 共享存储轮次：保存/查询/更新采样峰值 **2078.17 → 1530.11 MiB**；但流式还原带来额外计算，保存 **0.145 → 0.922 s**，最长单次更新等待 **177 → 942 ms**。不能描述为所有指标同时改善。
- 最终路径表轮次的桌面实测约 642 万条有效记录：Phase 2 完成时 `footprint` 为 **600 MB**，约 3.5 分钟后 **612 MB**，`vmmap` 启动历史峰值 **834.3M**。这是当轮短时 GUI 测量，单位和负载均不同于上表；不是本次日志整理时重新测量。

## 验证与限制

- 各轮已有快速回归、ASan/UBSan、分页桥接和 Release 构建记录。最终路径表轮次记录快速回归 **12,250 项通过**，ASan/UBSan 定向 **773 项通过**。
- 固定快照保存再重载后，6,460,706 条记录的名称、路径、大小、修改时间和类型均无差异；inode/devId 按新约定为 0，6,381,948 条有效路径均能反查原记录。
- 路径表轮次的 TSan 虽有 297 项断言通过，仍报告一处 `__block` 结果数组警告。随后 `110ed3b` 改为捕获线程槽指针，见 [算法日志](147-query-and-prefix-removal.md)；不能把此前日志写成 TSan 无警告通过。
- 查询压缩存在解码成本，部分名称和目录查询曾回退；后续专用扫描与 Top-K 改善了部分负载，详见算法日志。
- 全量保存仍有 I/O 写放大，保存时更新仍会排队；未证明长期运行、全盘重建、压缩或启用全文索引时始终低于 1 GiB。结构容量、RSS、物理足迹与采样峰值不混用。
