# 147：查询扫描、Top-K 与目录批量删除优化

日期：2026-10-22。汇总 `86425e0` 中的查询优化，以及 `110ed3b`、`84c26b7`、`bb6681a` 的后续改动。相关存储布局见 [146：内存优化](146-resident-memory-optimization.md)。

## 路径候选与匹配语义

取消常驻路径 trigram 后，名称/扩展名索引足够有选择性时优先使用它们；否则扫描去重父目录，经目录到记录映射生成候选。候选超过总记录的四分之一时回退全扫描，限制临时候选开销；Phase 2 未完成时也走完整扫描。

同步修正内部 `__pathseg` 的扫描语义：父目录约束只匹配父目录，不再把文件名混入。OR/NOT 中的非必需路径条件不能用于裁剪候选。结果按 **priority、pathLen、record ID** 排序，保证候选遍历顺序变化后截断结果仍稳定。

固定快照中 16 条样本的数量与有序 ID 哈希前后一致；7 条目录/OR/NOT 查询分别以无限制和 10,000 条上限，与全扫描完整有序数组核对。此前直接停用旧索引的实验出现过语义差异，因此性能对照的基线也同步了语义与排序修正。

证据：[取消路径 trigram 报告](../audits/2026-10-22/remove-path-trigram/report.md)。

## 专用扫描与有界结果集

- 合并候选集与完整扫描中重复的评估循环。单个 SUBSTRING 在进入工作线程扫描前选择专用循环，大小写敏感/不敏感分别实例化；复杂表达式继续走 AST，RE2 沿用各线程独立缓存。
- 名称已经命中时不再拼父路径或完整路径；其他条件只读取实际需要的字段。
- `DirectoryPool.matchesSegments` 直接沿父目录组件匹配，保留邻接、跨级及从右向左的规则。上下文大小写覆盖或长度截断等情况回退平坦字符串路径。
- 有结果上限 K 时，每个线程仅保留局部前 K，再合并排序取得全局前 K，避免先收集所有命中。纯类型/大小/时间条件沿用记录号排序，每段取得最早 K 条后可提前结束。
- `maxResults=0` 仍返回全部结果；输入候选集和无限制结果缓冲没有变成常数大小。查询结果数量仍受接口上限约束，没有新增全量命中计数保证。
- 按工作线程相对起点定期检查取消代数，避免分段起点不对齐导致跳过检查。

同一份约 638 万条有效记录的固定快照，每条查询预热后运行五次取中位数，最多返回 10,000 条，单位 ms：

| 查询 | 本轮前 | 本轮后 |
|---|---:|---:|
| `readme` | 6.157 | 5.802 |
| `*.swift` | 0.884 | 0.912 |
| `type:folder` | 6.643 | 2.090 |
| `/Applications/` | 10.531 | 6.283 |
| `MacEverything/a` | 112.592 | 40.341 |
| `com.apple.Safari/a` | 116.373 | 40.146 |
| `site-packages/a` | 121.971 | 52.558 |

这是共享存储压缩之后、专用扫描优化前后的对照，不能和其他轮次直接拼接为统一加速比，也不能宣称所有查询更快。

独立进程中按 1 ms 间隔采样，首次执行 `size:>=0` 的额外物理足迹 **179.24 → 2.36 MiB**，NOT 高命中查询 **187.16 → 2.82 MiB**；这是两个有限结果查询的临时分配收益，不是索引常驻容量减少，也可能漏掉更短的瞬时尖峰。

该轮快速回归 **12,231 项通过**，ASan/UBSan 定向 **694 项通过**；16 个样本的数量及有序 ID 哈希一致。Part 77 覆盖多种查询上限、索引与全扫描一致性、稳定排名；另有 3,000 余条目录匹配对照。

证据：[查询与峰值报告](../audits/2026-10-22/win-inspired/report.md)。专用循环参考了 Everything 静态分析的结构线索；Top-K 和父目录组件匹配是本项目的实现选择，不代表恢复了 Windows 样本中的相同算法。

## 前缀删除先查目录

`84c26b7` 将 `removeByPathPrefix`、`batchRescanPrefix` 共用的 `pathRecordsUnder` 从逐记录重建路径，改为扫描约 70 万个去重目录，再展开命中目录的记录，避免遍历约 638 万条文件记录。

- 用目录长度先排除不可能命中的项；匹配父目录拼接形式是否以「前缀/」开头。
- 单独按完整路径查找「恰好等于前缀」的记录，覆盖位于更浅目录中的匹配项。
- 只保留路径表中有映射的记录，排序、去重后再删除，维持重复记录处理及 WAL 顺序。
- Phase 2 尚未完成、目录映射不完整时退回原来的全量扫描。

同一固定快照的单次顺序对照，单位 ms：

| 操作 | 修改前 | 修改后 |
|---|---:|---:|
| 小目录删除（28 条） | 2914.5 | 51.6 |
| 子树重扫删除（2 条，无新增） | 2956.6 | 57.8 |
| 大目录删除（41,562 条） | 4275.9 | 1408.5 |

这仍是一次目录扫描，并非按命中子树大小访问的目录树遍历。小前缀固定开销约 50 ms；大前缀当时仍受逐条倒排表删除限制。

该轮快速回归 **12,253 项通过**。新增前缀与暴力标准答案对照、孤立重复记录保护、Phase 2 回退检查及变异测试。ASan/UBSan 指定核心分组通过；同次运行的 FSEvents 集成有 5 项环境失败，基线同样失败，不能写成整次运行全部通过。

证据：[目录前缀删除报告](../audits/2026-10-22/prefix-remove-dirs/report.md)。

## 按倒排表批量维护删除

`bb6681a` 继续优化大前缀删除：当命中 **至少 64 条**记录时，按 trigram 分组，一张表调用一次 `PackedPostingList::eraseSorted`；扩展名索引也按键分组一次过滤，减少逐条删除带来的重复字节搬移。

差分表边解码边原地重写，合并被删除项相邻差分；重建受影响检查点，处理尾部与 `last_`，并维护定位步数上限。批量删除与逐次 `erase` 的内容及重复编号语义一致。随后仍按原顺序处理 WAL、路径表、墓碑、有效计数与最近文件缓存。少于 64 条继续使用原路径。

同一固定快照，交替运行两个版本各两次：

| 操作 | 上轮版本 | 批量维护后 |
|---|---:|---:|
| 大目录删除（41,562 条，ms） | 1396.9 / 1430.1 | 245.7 / 252.8 |
| 删除后的有效记录数 | 6,340,356 | 6,340,356 |
| 小目录删除（28 条，ms） | 51.29 / 50.45 | 54.08 / 51.87 |

大前缀写锁时长由约 **1.4 s 降到 0.25 s**；小前缀仍走原实现，波动不作为提速结论。

该轮快速回归 **12,227 项通过**，ASan 定向 **181 项通过**。300 轮随机差分表测试对照逐条删除；引擎测试逐张核对 trigram/扩展名表、有效计数、最近文件和 WAL 顺序；变异测试覆盖尾值和重复记录号。各轮测试总数来自原始日志，不表示本次重新执行或可以相加。

证据：[批量倒排表删除报告](../audits/2026-10-22/batch-index-removal/report.md)。这两轮删除优化当时未重启 GUI 专项复测，性能结论来自核心基准；其余单路径删除、更新、WAL 回放和压缩路径未改。

## 并行结果槽的生命周期修正

`110ed3b` 将 `dispatch_apply` 中的 `__block` 结果 vector 改为栈上 vector 加线程槽指针捕获，避免依赖 block 复制时的容器搬移和 libdispatch 内部时序。旧 TSan 日志中的警告与该位置对应；已有报告不能视为修复后重新运行的无警告证明。

本条依据已有源码、提交和审计结果整理，没有重新运行算法基准或测试。
