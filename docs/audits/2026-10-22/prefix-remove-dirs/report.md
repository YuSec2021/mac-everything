# 前缀删除改为按目录查找

日期：2026-10-22。基线为 ce0f229（第二阶段与 TSan 修复）。只改了 `SearchEngine::pathRecordsUnder`，`removeByPathPrefix` 和 `batchRescanPrefix` 都通过它取得要删除的记录。内存结构和磁盘格式均未改动。

## 问题

原实现遍历路径表中的每一条记录，逐条调用 `lowerFullPath` 拼出完整路径，再比较前缀，整个过程持有写锁。在 638 万条记录上，哪怕前缀下只有几条记录，也要扫描近 3 秒。FSEvents 触发的子树重扫（`batchRescanPrefix`）每次都会走这条路径，期间查询全部被阻塞。

## 做法

匹配规则不变：小写完整路径等于前缀，或者以「前缀/」开头。

- `lowerFullPath(r) = makeFullPath(小写目录, 小写名)`，等于「目录的拼接形式 + 文件名」；拼接形式指目录为空或已以 `/` 结尾时保持不变，否则在末尾补一个 `/`。
- 因此，一条记录要以「前缀/」开头，它所在目录的拼接形式就必须以「前缀/」开头。可能落在更浅目录里的只有一种情况：完整路径恰好等于前缀的那一条记录。

实现：
- 先按长度跳过不可能匹配的目录，再还原其余目录的小写路径做比较。目录总数约 70 万，远少于 638 万条记录。
- 命中目录下的记录从 `pathIdxToRecords_` 取出，再单独用 `findPathRecord` 查一次「路径等于前缀」的那条记录。
- 只保留路径表里有映射的记录，所以孤立的重复记录和原来一样不会被删除。
- 结果按记录号排序、去重，WAL 的写入顺序不变。
- Phase 2 完成之前，`pathIdxToRecords_` 只包含新追加的记录，这时退回原来的全量扫描。

## 固定快照耗时

输入：/tmp/maceverything-memory-2/index.v6，只读。两个版本都设置 `MallocLargeCache=0`，用同一个只调用公开 API 的基准程序（mutbench.cpp）顺序各跑一次。单位 ms，查找和更新为 µs/次。

| 操作 | ce0f229 | 修改后 |
|---|---:|---:|
| 删除一个小目录（28 条） | 2914.5 | **51.6** |
| batchRescanPrefix `/Library/Fonts`（删 2 条，无新增） | 2956.6 | **57.8** |
| 删除 `/System/Library/Frameworks`（41,562 条） | 4275.9 | 1408.5 |
| indexForPath 命中 / 未命中（µs） | 1.19 / 0.98 | 1.25 / 1.05 |
| updateByPath（µs） | 109.5 | 108.9 |

小前缀的耗时现在基本就是扫描目录的固定开销，约 50 ms。大前缀扣掉这部分，剩下约 1.36 s 花在逐条删除记录时维护索引上（平均每条约 33 µs，主要是从 trigram 倒排表中删除），这部分本轮没有改。两个版本删除的记录数、删除后的有效记录数完全一致。

## 验证

- 快速回归：12,253 项通过，0 失败（tests.log）。新增 3 项：
  - 20 个前缀与暴力计算的标准答案逐条对照：删除条数一致，删除后每条记录的存活状态一致。覆盖根目录、只差大小写、名字是另一目录前缀（`bc` 与 `bcd`）、尾斜杠与双斜杠、多层嵌套、文件的完整路径、不存在的路径、空串。
  - 批量重扫产生的孤立重复记录不会被删除。
  - Phase 2 尚未完成时（从 v6 加载后立即删除，并夹带一条新追加的记录），退回全量扫描且结果正确。
- 变异测试：临时去掉「单独查找与前缀相等的记录」这一步，第一项测试在前缀 `/a/bc` 上失败；恢复后通过。
- AddressSanitizer + UndefinedBehaviorSanitizer：Part 3、3b、3d、7、7b、7c、8、21、47、48、58、62、64、69、71、72、77 全部通过，没有报告错误（asan.log）。同一次运行里 Part 4（FSEvents 集成）有 5 项失败：它只测 `FileSystemWatcher`，监视 `/tmp` 下的目录；在当前命令环境里，ce0f229 的普通构建同样失败这 5 项，属于环境收不到 FSEvents。真实 FSEvents 的增删已在桌面应用上验证过（见 path-table-dir-runs/report.md）。

## 范围与限制

- 没有重启桌面应用复测。
- 大前缀的瓶颈现在是逐条维护索引；按 trigram 批量删除能进一步缩短，本轮没有做。
