# 内存优化：目录树、共享大小写数据与差分倒排表

日期：2026-10-22。按此前第 2 → 3 → 4 项顺序实施。基线为已取消路径 trigram 的版本。

## 改动

- DirectoryPool 用目录组件和父目录 ID 保存共享前缀；文件仍持有稳定的目录编号。路径按需还原，每个查询工作线程仅缓存上一个父目录。目录移动、删除和重扫沿用现有增量维护，孤立组件在压缩时回收。
- 原始路径和小写路径共用一棵目录树；已经是小写的组件共用字节。Unicode 上下文大小写、无效 UTF-8 等特殊情况保留整路径转换的结果，避免改变匹配语义。
- FoldedNamePool 将原始名称与小写名称合并。相同时共享字节，不同时保留两个偏移及各自长度，支持转换后 UTF-8 长度变化。快照独立拥有数据。
- 名称倒排编号由固定 24 位改为 varint 差分编码。稀疏检查点支持随机定位，顺序迭代连续解码；插入和删除只重编码相邻差分并调整后续检查点，避免首次更新时解压整张表。
- 构建先统计每张表的编码字节与检查点容量，再准确分配。启动转换的四个字符串输入池使用只读文件映射，保留 CRC、长度、条目范围、成对数量与目录编号校验。映射在转换完成后释放，常驻结构仍是内存数据。
- v6 磁盘格式不变；保存时以约 64 KiB 的缓冲块还原字符串并计算 CRC，避免同时生成完整平坦池。COW 压缩使用一份共享大小写快照，避免复制两套名称。未新增依赖。

## 同一份固定索引对照

数据：6,460,706 个记录位置，6,381,948 条有效记录、707,177 个唯一父目录。输入是 /tmp/maceverything-memory-2/index.v6，744,894,044 字节；SHA-256 为 46b8eb2f7e52153d736662a9ba6a817d69bf7e54b5f5c0b772b9c854daace73a。所有测试只读此固定输入。单位 MiB。

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 索引就绪时进程物理内存足迹 | 1573.03 | 1268.56 |
| 原始及小写名称池容量 | 约 334.30 | 218.87 |
| 名称 posting 及检查点容量 | 307.75 | 139.30 |
| 保存＋查询＋100 次增量更新采样峰值 | 2078.17 | 1530.11 |
| 保存完成后重载有效记录数 | 6,381,948 | 6,381,948 |

就绪足迹减少 304.47 MiB（19.4%）；保存与更新阶段采样峰值减少 548.06 MiB（26.4%）。目录树数组为 32.17 MiB，另有组件边 B-tree 等开销；不能将它直接当作目录结构总占用。固定输入没有触发整路径小写覆盖项。

保存耗时 0.145 → 0.922 秒；并发查询最长 1.06 → 6.87 ms。保存仍通过 mutation gate 暂停写入，最长一次更新耗时 177 → 942 ms（包含等待保存的时间）。本轮没有消除保存阻塞或保证任意时刻低于 1 GiB。

新写出的 v6 文件为 740,159,038 字节；旧版本读取器已成功加载，并返回相同的查询数量与有序编号哈希。

## 验证

- 12,095 项完整快速回归通过，0 失败。包含原有路径、大小写、分页、v5/v6 持久化、WAL、并发压缩与增量更新测试。
- 新增目录树的根目录、相对路径、重复斜杠、最长字符串、Unicode、非法 UTF-8、复制与扁平格式往返测试。
- 新增共享名称的相同字节指针、不同大小写及 UTF-8 长度、复制快照、删除增长与旧格式往返测试。
- 差分表与 vector 进行 4,000 次随机插删、lower_bound、随机定位及顺序迭代对照；另运行 16,000 次混合更新的独立 AddressSanitizer＋UndefinedBehaviorSanitizer 检查，覆盖删空、检查点迁移和 UINT32_MAX。
- AddressSanitizer 定向核心测试 515 项通过，0 失败（Part 8、21、47、48、58、64、69、71、72）。
- Objective-C++ 桥接快照测试通过：分页顺序、偏移边界、删除、压缩失效与引擎生命周期。
- 固定大索引的 16 个样本查询在修改前、修改后、旧读取器重载新保存文件后，结果数量和有序 ID 哈希全部相同。7 条目录、OR、NOT 查询分别检查无限制及 10,000 条上限，与完整扫描的有序数组相等，每个版本 14 项。
- Release Xcode 构建成功并已重启。当前桌面索引约 639 万条有效记录，vmmap 当前物理足迹约 1.4 GiB，启动峰值约 1.5 GiB；空闲 CPU 单次采样 0%。实际数据和固定快照不同，不将两者直接相减。
- 主窗口输入 MacEverything/README 返回 6 条文件及正确路径；关闭主窗口后通过 Search → Menu Bar Search… 验证共享结果。菜单栏面板中 MacEverything/a 返回 1,122 条，首批 100 条、约 128 ms；清空查询与 Escape 关闭正常。

## 限制与后续

还没有达到 1 GiB 以内：就绪固定样本约 1.24 GiB，实际桌面进程约 1.4 GiB，增量更新后的容量增长会高于刚加载就绪值。保留名称倒排表和全盘范围。未实测长时间驻留、全盘重建峰值、启用全文索引后的占用；系统菜单栏图标直接鼠标点击本轮未重复验收，面板使用应用 Search 菜单入口验证。

若继续冲击 1 GiB，需要进一步评估较冷元数据的磁盘映射或按需读取，以及路径定位表、目录映射的容量；本轮没有声称已验证这些后续收益。

## 原始数据与复现

当前核心性能脚本 profile.cpp；保存及并发测量脚本 save-profile.cpp。以 C++20、-O2、-fno-access-control 编译并链接项目原有 RE2、Abseil、CoreServices。保存脚本还接收一个独立输出路径；不会修改输入。独立差分表检查：clang++ -std=c++20 -O1 -g -fsanitize=address,undefined -IMacEverything/Core delta-property.cpp。
基线源码备份 /tmp/maceverything-next-memory-before/Core。before.txt、after.txt 为最终顺序运行；save-before.txt、save-after.txt 为另一次保存负载；old-reader.txt 是旧读取器读取新保存格式的校验。tree.txt、tree-memory.*、combined.txt、final.txt 为中间实验，不能代替最终对照结果。第一版独立双目录树曾提高足迹，最终采用单树共享小写组件并减少加载临时分配。
