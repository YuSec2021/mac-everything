物理内存减少 312.60 MiB（16.6%）。该差值还包含倒排表容器与分配器开销，不能与 posting 数据大小直接等同。启动时间为单次顺序运行，受磁盘缓存和系统调度影响，不作为稳定加速承诺。

桌面应用重新构建并启动后，实际实时索引约 639 万条记录；vmmap 显示当前物理占用约 1.5 GiB、启动峰值约 2.1 GiB。ps 的单次 CPU 采样为 0.3%。实际进程数据见 live-vmmap.txt。该方案尚未达到 1 GiB 以内。

## 正确性与验收

- 修正内部 __pathseg 在完整扫描中把文件名也当父目录的问题；父目录约束现在统一只检查父目录。
- 相同评分与路径长度的结果按记录编号稳定排序，避免候选遍历顺序改变截断结果。
- 为公平比较，基线核心只同步上述语义和排序修正，保留原路径 trigram；备份位于 /tmp/maceverything-remove-path-before/Core。
- 在固定大索引上，7 条目录/OR/NOT 查询分别测试无限制及 10,000 上限，优化查询与全扫描的完整有序 ID 数组均相等（每个版本 14 项）。
- 完整快速回归：12,080 通过，0 失败。新增目录约束、多个路径条件、邻接/跨级、OR/NOT、limit、添加、删除、移动、压缩和子树重扫测试。
- AddressSanitizer 定向测试（8、21、47、48、58、64、69、71）：485 通过，0 失败；未报告内存安全错误。
- Release Xcode 构建成功，新版本已重启。桌面 MacEverything/readme 返回 5 条；关闭主窗口后通过 Search → Menu Bar Search… 验证弹出搜索及无结果状态。

未做长期持续运行与全盘重建峰值测试；系统菜单栏图标的直接鼠标点击未在本轮重复验收。保留名称倒排表，因此内存仍高于 1 GiB。
